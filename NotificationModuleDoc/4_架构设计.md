# Android通知消息抓取模块 - 架构设计文档

## 📐 模块架构

### 整体架构图

```
┌─────────────────────────────────────────┐
│     主程序 (MainActivity, Service等)     │
├─────────────────────────────────────────┤
│   NotificationModuleAPI (对外接口)      │  ← 主程序只需调用此层
├─────────────────────────────────────────┤
│ NotificationCaptureService  │  Filter   │
│   (消息捕获核心)            │  (筛选)   │  ← 业务逻辑层
├─────────────────────────────────────────┤
│ MessageModel (数据模型)                  │  ← 数据层
└─────────────────────────────────────────┘
```

### 各层职责

| 层级 | 类名 | 职责 | 特点 |
|-----|------|------|------|
| **应用层** | 主程序 | 调用模块接口 | 不需要了解模块内部实现 |
| **API层** | NotificationModuleAPI | 对外暴露高级接口 | 简洁易用，隐藏复杂度 |
| **服务层** | NotificationCaptureService | 从系统通知栏捕获消息 | 核心逻辑，独立可测 |
| **筛选层** | NotificationFilter | 实现多种筛选策略 | 灵活扩展，支持自定义 |
| **数据层** | MessageModel | 消息数据封装 | 纯数据类，无业务逻辑 |
| **测试层** | NotificationModuleTest | 独立单元测试 | 可拆分，局部可验证 |

## 🧩 核心类详解

### 1. MessageModel（数据模型）

**职责**：封装消息数据  
**特点**：纯数据类，无业务逻辑

```java
public class MessageModel {
    String packageName      // 应用包名
    String appName          // 应用名称
    String title            // 消息标题
    String content          // 消息内容
    String groupName        // 群组名称
    String senderName       // 发送者
    long timestamp          // 时间戳
    int notificationId      // 通知ID
    
    // 多种toString方法
    toString()              // 完整格式
    toSimpleString()        // 简洁格式
    toJsonString()          // JSON格式
}
```

---

### 2. NotificationFilter（筛选器）

**职责**：定义和实现消息筛选策略  
**设计模式**：Strategy Pattern（策略模式）

```
┌──────────────────────┐
│  IMessageFilter      │ (接口)
│  - match()           │
└──────────────────────┘
         ↑
    ┌────┴────┬────────┬─────────────┐
    │          │        │             │
┌───┴────┐ ┌──┴──┐ ┌───┴──┐ ┌────────┴──────┐
│Package │ │Group│ │WeChat│ │AICourseGroup  │
│NameF.. │ │Name │ │Filter│ │Filter         │
└────────┘ └─────┘ └──────┘ └───────────────┘

┌──────────────────────────┐
│  CustomRuleFilter        │ (用户自定义)
│  - targetPackageName     │
│  - targetGroupName       │
└──────────────────────────┘

┌──────────────────────┐    ┌──────────────────────┐
│CompositeAndFilter    │    │CompositeOrFilter     │
│(AND逻辑)            │    │(OR逻辑)              │
│多个筛选条件同时满足  │    │多个筛选条件满足其一  │
└──────────────────────┘    └──────────────────────┘
```

---

### 3. NotificationCaptureService（捕获服务）

**职责**：从系统通知栏捕获消息并进行筛选  
**特点**：核心业务逻辑，独立可测试

```java
public class NotificationCaptureService {
    // 核心方法
    captureLatestMessage()           // 获取最新
    captureAllMessages()             // 获取所有
    captureAndFilterLatest()         // 捕获并筛选最新
    captureAndFilterAll()            // 捕获并筛选所有
    
    // 辅助方法
    setMessageFilter()               // 设置筛选器
    extractMessageFromNotification() // 提取消息
    extractGroupNameFromWechatNotification() // 特殊处理微信
}
```

---

### 4. NotificationModuleAPI（对外接口）

**职责**：为应用层提供统一、简洁的接口  
**特点**：隐藏内部复杂度，易于集成

```java
public class NotificationModuleAPI {
    // 基础接口
    captureLatestMessageAsString()
    captureAllMessagesAsString()
    
    // 自定义筛选（推荐）
    filterLatestMessageByRule(包名, 群聊)    // ⭐最常用
    filterAllMessagesByRule(包名, 群聊)
    
    // 默认预设
    filterWeChatMessage()            // 微信筛选
    filterAICourseGroupMessage()     // AI课程筛选
    filterWeChatAICourseMessage()    // 组合筛选
    
    // 高级接口
    setCustomFilter()                // 自定义筛选器
    captureLatestMessage()           // 获取原始对象
}
```

## 🎯 设计原则

### 1. 单一职责原则 (SRP)

```
❌ 错误设计：
NotificationModule (内部包含捕获+筛选+日志+测试)

✅ 正确设计：
MessageModel                    // 仅负责数据
NotificationFilter              // 仅负责筛选
NotificationCaptureService      // 仅负责捕获
NotificationModuleAPI           // 仅负责接口
NotificationModuleTest          // 仅负责测试
```

### 2. 依赖倒置原则 (DIP)

```java
// ❌ 错误：直接依赖具体类
captureService.setFilter(new WeChatFilter());

// ✅ 正确：依赖抽象接口
captureService.setFilter(filter);  // filter是IMessageFilter接口
```

### 3. 开闭原则 (OCP)

```java
// 不修改现有类，只需扩展新的筛选器
public class MyCustomFilter implements IMessageFilter {
    @Override
    public boolean match(MessageModel message) {
        // 自定义逻辑
    }
}
```

### 4. 接口隔离原则 (ISP)

```java
// 对外只暴露必要的接口
public class NotificationModuleAPI {
    public String filterWeChatAICourseMessage()     // 易用
    public String filterLatestMessageByRule()       // 灵活
    public String captureLatestMessageAsString()    // 基础
}

// 复杂的内部实现隐藏
// private NotificationCaptureService
// private NotificationFilter
```

## 🔌 扩展点

### 1. 自定义筛选器

```java
// 用户可以创建自己的筛选器
public class CustomFilter implements NotificationFilter.IMessageFilter {
    @Override
    public boolean match(MessageModel message) {
        // 自定义逻辑：按发送者、时间、内容等筛选
        return message.getSenderName().equals("特定用户");
    }
}

// 使用
api.setCustomFilter(new CustomFilter());
```

### 2. 复合筛选器

```java
// 组合多个筛选条件
List<IMessageFilter> filters = new ArrayList<>();
filters.add(new WeChatFilter(null));
filters.add(new CustomGroupFilter());
filters.add(new TimeRangeFilter());  // 自定义

CompositeAndFilter composite = new CompositeAndFilter(filters);
api.setCustomFilter(composite);
```

## 📝 总结

### 模块特点
✅ **高内聚** - 各类职责单一且内聚  
✅ **低耦合** - 依赖抽象而非具体实现  
✅ **易扩展** - 支持自定义筛选器  
✅ **可拆分** - 各部分可独立测试  
✅ **易集成** - 简洁的API接口  

### 使用建议
1. **新手**：使用预设接口 `filterWeChatAICourseMessage()`
2. **中级**：使用灵活接口 `filterLatestMessageByRule()`
3. **高级**：实现自定义 `IMessageFilter` 接口

### 最佳实践
- 在初始化时创建 `NotificationModuleAPI`
- 根据需求选择合适的过滤接口
- 通过 Logcat 观察日志验证逻辑
- 使用 `NotificationModuleTest` 进行单元测试
- 关注权限和 Android 版本兼容性
